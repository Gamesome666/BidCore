# BidCore · 8 分钟演示脚本

> 目标：用一条“已完成的真实运行”和一条“停在人工门禁的运行”，在 8 分钟内讲清
> **工作台数据 → 工作流 → DAG 并行 → 质量返工 → 人工四动作 → 多级/SLA → 版本对比 → 导出**。
>
> 演示前 30 秒准备（不要占用讲解时间）：
>
> ```bash
> cd bidcore
> node server/index.mjs            # 若已启动则跳过；默认 http://127.0.0.1:5192
> node tools/demo.mjs              # 幂等造数：技术方案全流程 + 待审运行 + 已完成运行
> ```
>
> 记下 `demo.mjs` 输出的 `waitingRun`、`reviewTask`、`completedRun`、`ADMIN_TOKEN`。
> 现场网络不稳时 `demo.mjs` 会把模型切 mock 再恢复，无需手工操作。
>
> 建议窗口 1440×980，浏览器缩放 100%，提前登录 `admin/admin123`。
> 工作台用 `#/projects/1?tab=plan`，审核详情用 `#/reviews/<id>`；两条路由均已验证可用。

---

## 0:00–0:40 开场与登录

**操作**
1. 打开 `http://127.0.0.1:5192`，展示登录页。
2. 用 `admin / admin123` 登录。

**预期画面**：左侧深色导航（总览 / 标书生成 / 人机协同 / 资产与团队 / 系统），
顶栏项目切换器 + 「启动工作流」，左下角「实时通道已连接」。

**讲解词**
> BidCore · 标序，一个可人工干预的 Multi-Agent 投标平台。
> 后端是 Node 24 内置的 http + node:sqlite，前端是零构建的原生 ES Module，**没有任何 npm 依赖**。
> 任何机器上 `node server/index.mjs` 就能跑，断网也能完整演示——因为我们内置了确定性 Mock 写作器。

## 0:40–1:40 工作台总览

**操作**
1. 进入 `#/dashboard`。
2. 指四个指标卡：进行中项目 2、运行中任务 1、待我审核、质量均分 92。
3. 指「待办审核」里的 `review-1`（剩余 SLA 倒计时）。
4. 指「质量趋势」折线和「能力雷达」。

**预期画面**：指标卡、待办审核、最近运行（含“等待人工 / 已取消 / 已完成”三种状态）、
质量趋势（91→79→93）、能力雷达（完整性/准确性/技术性/匹配度/规范性）。

**讲解词**
> 这是对标 yibiao 的 Dashboard，但我们把“待办”和“质量”放到了第一屏。
> 质量趋势的 91→79→93 不是三次不同项目，而是**同一条运行**里质量门禁的两次评估：
> 第一次 91 分通过；下游技术方案被评委发现占位符，返工后 79 分；再返工到 93 分才放行。
> 下面雷达的五维，就是 Self-Loop 的打分口径。
>
> （若顶部出现“聚合接口异常…已降级”提示，可顺带说明：这是并行开发中的前后端字段口径问题，
> 数据已用降级聚合正常展示，缺陷已记录。）

## 1:40–3:00 项目工作台：技术方案不是黑盒

**操作**
1. 左侧「项目管理」→ 打开 `XX市政务云平台运维服务项目`（或直接 `#/projects/1?tab=plan`）。
2. 「概览」tab：指阶段进度、质量分、待审。
3. 切「招标解析」：左侧原文、右侧 35 条要求（废标 6 条红色标记）。
4. 切「技术方案」：六步进度条全绿；左侧目录 29 节点/21 叶；右侧 Markdown 编辑器。
5. 切「响应偏离」：35 行，状态“已确认”（人工确认过）。
6. 切「废标检查」：6 条废标项、未响应 0；「查重」最高相似度 83.1%。

**预期画面**
- 技术方案：步骤条 `招标解析 → 目录生成 → 全局事实 → 正文生成 → 检查 → 导出`；
- 目录树带字数与“已生成/未生成”状态；右侧编辑器可保存单章；
- 偏离表：条款 / 招标要求 / 响应 / 偏离 / 证据，行内可编辑；
- 废标检查：veto 条目与响应完整性；查重：重复对列表。

**讲解词**
> yibiao 的技术方案是“单文档全量状态 RPC”，我们保留了这个契约，但把它做成**七步可重放的流水线**：
> parse → outline → facts → content → checks → deviation → export，每一步都能单独触发、单独重跑。
> 这里 35 条要求、29 个目录节点、21 章 1 万字正文，全部由项目名和招标原文确定性派生，所以可复现。
> 偏离表是**导出硬门禁**：没人工确认，导出接口直接 409。
> 废标检查不是提示，而是会进入质量规则：废标条款未响应 → veto → 质量分封顶 59 → 强制人工。

## 3:00–4:00 启动工作流：DAG 与并行

**操作**
1. 点顶栏「启动工作流」，项目选政务云，目标留空，点「启动」。
2. 自动跳到 `#/run/<runId>`。
3. 指 DAG：parse-tender → knowledge → bid-strategy → 质量门禁 quality-1 → 人工审核 review-1 →
   tech / commercial 并行 → compliance → quality-2 → review-2 → export。
4. 指右侧 Supervisor 面板：计划 v2、并行批次、决策流水（rework / replan / plan.revised）。
5. 指预算条：13K tokens / 3M，Agent 调用 2/40。

**预期画面**：节点颜色（灰/蓝/橙/绿/紫/红），同层并行节点并排；右侧决策流每条带时间与目标。

**讲解词**
> Supervisor 只做一件事：产出计划，不写内容。计划要过 7 条校验（节点数、key 唯一、依赖存在、
> 无环、必须有 export 终结点……），模型输出不合格就自动落到 11 节点 FallbackPlan，绝不中断。
> 调度是确定性的：默认 2 个并行槽，tech / compliance / doc 强制串行，人工门禁与导出不并行。
> 所以 DAG 上看到的并行批次是**真实调度决策**，不是画出来的。
> 预算超过 85% 会告警并跳过第二次评委，超过 100% 直接暂停，避免演示烧穿额度。

---

## 4:00–5:00 质量返工：Self-Loop 怎么工作的

**操作**
1. 运行详情点「质量报告」，或左侧「质量报告」。
2. 选已完成的运行（`completedRun`）。
3. 指迭代趋势：quality-1 #1 91 pass；quality-2 #1 79 revise；quality-2 #2 93 pass。
4. 展开「规则证据」：ACC-02 发现 1 处占位符/待补充 → 目标 Agent tech。

**预期画面**：五维雷达、14 条规则证据（可展开证据）、评委 rubric、迭代趋势、人工接受现状按钮。

**讲解词**
> 质量不是“导出前 lint”，而是驱动返工的闭环。
> 规则轨是 14 条确定性规则，五维加权 30/25/20/15/10；评委只是受限 rubric，最多影响总分 15.5 分，
> 不允许模型单方面决定通过。
> 79 分那次是因为技术方案里有“待补充”占位符，命中 ACC-02；系统按“缺陷码 → 目标 Agent”表
> 把 tech 节点重新入队，quality-2 自身失效，等 tech 重跑完再评一次，93 分才 pass。
> 三轮不达标或命中废标就熔断转人工，不会无限烧 token。

## 5:00–6:40 人工门禁：四动作与并发保护

**操作**
1. 左侧「审核中心」→ 打开停在 `review-1` 的任务（`reviewTask`）。
2. 指左侧产物正文、右侧质量卡、规则证据、SLA 倒计时、级别进度、上游意见。
3. 指底部四个按钮：通过 / 驳回 / 修改 / 要求重新分析。
4. 演示「驳回」：目标下拉只列祖先 Agent（parse-tender / knowledge / bid-strategy）；
   选一个下游 Agent（如 tech）会被后端拒绝：`409 REVIEW_TARGET_NOT_ANCESTOR`。
5. 演示「通过」：填写意见 → 提交；刷新审核中心，任务消失、运行继续。
6. 口头说明幂等与乐观锁：同一 `commandId` 重放返回同一结果；换 `commandId` 重复决策返回
   `409 REVIEW_ALREADY_DECIDED`。

**预期画面**：审核详情头部级别条 `第 1/1 级`、SLA `剩余 1 小时 58 分`、
产物 `quality:quality-1 v1`、质量 91 pass、四个动作按钮固定底部。

**讲解词**
> 这是 yibiao 最缺的一层：统一审核中心。
> 每条审核任务绑定一个被挂起的工作流节点；审核包一次给全：产物、质量、证据、版本 diff、
> 上游审核意见、级别进度、SLA。
> 驳回和修改**只能选祖先目标**——因为下游还没生成，让它“重做”没有意义；后端会做祖先校验。
> 提交必须带 `commandId`，重放幂等；并发第二个人提交会被乐观锁挡住，提示“已被他人处理”。
> 修改还支持结构化 edits，会落到产物的 `provenance.human_edits`，能追溯“这版是谁改的、改了什么”。

## 6:40–7:20 多级审核与 SLA

**操作**
1. 指审核详情的级别进度条：`第 1/1 级`（review-1，single 策略）。
2. 打开已完成运行的 `review-2`（若有历史任务）：`第 3/3 级`，展示 owner → biz → admin 三级。
3. 指 SLA：`截止 … · 提醒 …`；说明超时策略 `escalate`。
4. 指「转派」按钮（admin）：可改指派人并重置 SLA，写系统评论。
5. 指「评论」区：人工评论 + 系统评论（转派/升级）。

**预期画面**：级别进度、SLA 倒计时、转派弹窗、评论时间线。

**讲解词**
> 多级审核：第一级通过后自动生成第二级任务，gate 节点保持等待；最后一级通过才放行。
> 三级策略是 owner → 商务负责人 → 管理员，SLA 240/240/480 分钟，前两级超时自动升级，
> 第三级只提醒。升级会写系统评论和 `review.escalated` 事件，不会静默换人。
> 默认**不允许自动通过**；只有显式打开 `review.allow_auto_pass` 才会自动放行，演示环境保持关闭。
> 说明：SLA 到期升级需要真实等待 240 分钟，或改库把 `sla_due_at` 提前；现场不构造假数据，
> 逻辑已在 `review.mjs scanSla` 实现，代码可查。

## 7:20–7:50 版本对比与断点恢复

**操作**
1. 在审核详情点「与上一版对比」，展示双栏 diff（或 v1/v2 下拉）。
2. 指运行详情的事件流：`node.invalidated`、`quality.revise`、`supervisor.rework`。
3. 点「对账恢复」（或说明启动时自动 `reconcileAll`）。

**预期画面**：diff 双栏高亮；事件流按类型着色；节点抽屉显示 attempt/iteration。

**讲解词**
> 产物是版本化的：`(run_id, kind, version)` 唯一，重跑就 +1；“要求重新分析”不会删除旧版，
> 而是标 `superseded`，所以审核详情永远能切回 v1 对比。
> 断点恢复靠租约：节点执行持 45 秒租约，进程挂了最多 5 秒被回收重排；启动时还会强制对账
> 所有 running 运行，写 `run.recovered` 事件。审核任务在 SQLite 里，重启后仍在审核中心。

## 7:50–8:00 导出

**操作**
1. 回到项目工作台「导出」tab，指导出前置校验清单（全部通过）。
2. 点「导出 Word」，下载 `bidcore-p1-*.docx`（约 180KB）。
3. （可选）打开文档，展示封面、目录、章节、偏离表附录。

**预期画面**：校验清单全绿（解析/目录/正文/偏离确认/无占位符），导出历史出现新记录。

**讲解词**
> 导出前有五道硬门禁：解析、目录、正文、偏离表已确认、无占位符；任何一项缺失直接 409，
> 不是前端 toast 提示。Word 由零依赖 OOXML 写入器现场生成，带封面、目录、章节和偏离表附录。
> 到这里，一条“解析→写作→质量返工→人工审核→导出”的闭环就完整了。

## 附：现场应急预案

| 情况 | 处理 |
|---|---|
| 模型慢 / 网络断 | 设置页切 `mock`，或在演示前跑 `demo.mjs`（自动 mock 后恢复）；全链路仍可跑 |
| 审核详情 `#/reviews/:id` 打不开 | 改用 `#/review/<id>`（备用路由，同样可用） |
| 工作台 `#/projects/1` 落到列表 | 用 `#/projects/1?tab=plan` |
| 仪表盘顶部“聚合异常” | 已知前后端字段口径缺陷；数据仍有降级展示，可继续讲指标 |
| 端口被占用 | `PORT=5197 node server/index.mjs`，把浏览器地址改成 5197 |
| 没有待审任务 | 重新跑 `node tools/demo.mjs`（幂等，会补一条停在门禁的运行） |
| 想重置全部数据 | `node server/reset.mjs` 后重启，再跑 `demo.mjs` |

## 附：30 秒问答准备

- **和 yibiao 的关系？** 信息架构与兼容接口对齐，代码与视觉重写；补了 workflow / Self-Loop / HITL 三层。
- **为什么零依赖？** 任意机器免安装、免构建；SQLite 单文件可拷走；迁移 PostgreSQL 只需改类型。
- **质量分会造假吗？** 规则轨确定性、证据可定位；评委封顶 15.5%；人工可“接受现状”但只签字不改分。
- **人工能不能绕过质量？** 能，但必须走审核动作并留痕（决策/评论/事件/产物 provenance 四份记录）。
- **并签审核？** 策略与 UI 已就位，决策路径目前串行，列为后续（README §9.1/§17 已注明）。
